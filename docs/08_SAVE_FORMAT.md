# 08 — Save format (schema 40)

The code is `scripts/save/SaveGameSerializer.cs` and `scripts/save/SaveStore.cs` (pure C#), and the tests are in `tests/Simulation.Tests/SaveLoadTests.cs` and `SaveStoreTests.cs`.

## Where and when

- Saves are files in `user://saves/` (#60). On Windows that's `%APPDATA%\Godot\app_userdata\SpaceAutomationSandbox\saves\`.
  - **Manual saves** (`save_<date>_<time>.json`), made and named from the save screen (pause menu → Save).
  - **The quicksave** (`quicksave.json`): **F6** saves, **F9** loads (asking first if there's unsaved progress).
  - **Autosaves** (`autosave_1..3.json`), rotating (the oldest is replaced): every N minutes of play (Settings: off, 5, 10, 15 or 30; default 10) and when the window is closed. Stopping the game from the Godot editor kills the process without the close notification.
- Each file starts with a small **header** (name, time saved, play time, tick, seed, and the game's name), written before the sector, so the save list reads just the first bytes of each file. Saves without one (from before slots) are listed by file name and file time, and get one when renamed.
- **Continue** (title screen) loads the newest save that isn't broken. **Load** (title screen and pause menu) lists every save newest first, with load, rename and delete; the save screen adds "save as new" and overwrite. Overwriting, deleting, loading over unsaved progress and quitting with unsaved progress ask first.
- A save that can't be read is listed as **broken**, with the reason; nothing is moved or deleted behind your back. A load that fails leaves the current game as it was.
- Saves are written to `<file>.tmp` and then moved into place, so a crash mid-write keeps the previous save.
- The single save from before slots (`user://savegame.json`) moves into the folder as `save_from_before_slots.json` the first time the game starts.

## Principles

- **Full state, not "seed plus changes".** Bodies are stored completely, including mass and orbit, so retuning `SectorGenerator` never changes an existing save. The seed is kept for reference and future generation.
- **References use stable IDs**: body, craft and part IDs. Scene paths and list positions are never used.
- **Ship designs are embedded** in each craft, so a save survives edits to `data/blueprints`. Part *stats* come from the current `data/parts/parts.json`, so rebalancing a part applies to existing saves. If a saved design references a part that no longer exists, the load fails with a message naming it.
- **Deterministic:** the same state always produces byte-identical JSON. Doubles are written in round-trip form. Saving at any tick, loading and continuing gives exactly the state of a run that never stopped (tested).
- Not saved: the render interpolation fraction, camera and zoom. These are view state.

## Shape

```jsonc
{
  "schemaVersion": 19,
  "game": "SpaceAutomationSandbox",
  "playerCraftId": 1,                 // 0 = no player craft
  "sector": {
    "seed": 20261120,
    "tick": 1234,                     // fixed ticks since sector start (20/s)
    "nextOrderId": 3,                 // v3: build order ids are never reused
    "nextCraftId": 9,                 // v17, optional: craft ids are never reused (dismantled craft); older files derive it from the craft
    "nextBodyId": 30,                 // v17 (#27), optional: body ids are never reused (bodies mined away entirely are left out of "bodies")
    "discoveredKg": 0,                // v18, optional: mineable mass of star systems generated by warp (the mass ledger subtracts it)
    "researchPoints": 12.5, "unlockedTech": ["photovoltaics"], // v19, optional (#37): points to spend and techs researched
    "researchAllUnlocked": false,     // v19, optional: true for games started before research (everything open)
                                      // (further systems are ordinary bodies: their star is a Star placed on a fixed orbit around the home star)
    "tuning": { "drillRateMultiplier": 4, "refiningRateMultiplier": 1, "fabricationRateMultiplier": 1 },  // v8, debug; omitted when all 1
    "ejectedKg": { "slag": 12000 },   // v10: mass thrown out of the sector by ejectors; omitted when none
    "bodies": [
      { "id": 1, "name": "Primary", "kind": "Planet", "massKg": 5.0e15, "densityKgPerM3": 5500,
        "isMineable": false, "orbit": null },
      { "id": 2, "name": "Rock-1", "kind": "Asteroid", "massKg": 3.1e12, "densityKgPerM3": 2500,
        "isMineable": true, "depositsKg": { "metal": 497900 },   // v6: minable whole kg, part of massKg
        "orbit": { "parentId": 1, "radiusM": 26000, "periodS": 1800, "phaseAtZeroRad": 1.2 } }
    ],
    "crafts": [
      { "id": 1, "name": "Player",
        "design": { "id": "starter_ship", "name": "Starter prospector",
                    "cells": [ { "x": 0, "y": -3, "part": "drill" } /* ... */ ] },
        "position": { "x": 2381.0, "y": -6188.0 },   // centre of mass, sector metres
        "velocity": { "x": 60.1, "y": 46.3 },        // m/s
        "headingRad": 2.63,
        "controls": { "throttle": 0, "turn": 0, "brake": false },   // throttle −1..1 (negative = reverse); optional "strafe" −1..1, omitted when 0
        "targetBodyId": 2,                           // 0 = no target
        "targetCraftId": 0,                          // v5: target craft (exclusive with targetBodyId)
        "dockedToCraftId": 0, "dockPort": 0,         // v5: station and port index while docked
        "landedOnBodyId": 0,                         // v2: 0 = flying
        "landedOffset": null,                        // v2: craft centre minus body centre while landed
        "anchored": false,                           // v4: only while landed, and only with a clamp or foundation
        "miningRemainderKg": 0.25,                   // v6: drilled fraction of a kg not yet in cargo (0..1)
        "storedEnergyKJ": 41250.0,                   // v10: battery charge (0..capacity)
        "legacyFreePower": false,                    // v10: only written (true) for craft from pre-v10 saves
        "ejectionRemainderKg": 0.5,                  // v10: ejected fraction of a kg (0..1); omitted when 0
        "cruising": true, "cruiseFuelRemainderKg": 0.4,  // v12: cruise drive on, and burned fuel not yet whole kg; both omitted when off/0
        "partHealth": [ { "x": 0, "y": 2, "health": 0.6 } ], "partsLost": 1,  // v13: damaged parts (omitted when none) and parts broken off
        "labRemainderKg": 0.4,                       // v19, optional (#37): electronics used by the lab, not yet taken whole
        "gateLinkId": 31, "gateReadyTick": 4200, "jumpRequestTick": 0, "jumps": 2, // v18, optional (#22): a gate's link and when it can
                                                     // send again; a craft's place in a gate's queue (tick it asked); jumps made
        "yardOrder": { "kind": "Refit", "yardId": 2, "target": { /* design */ } }, "yardProgressKg": 40, // v17, optional (#56, #57):
                                                     // refit (with its target design), dismantle or pack-as-kit order and work on its current step
        "intactDesign": { /* design */ }, "repairProgressKg": 12.5, "serviceAtId": 2, // v16, optional (#3): blueprint before parts broke off
                                                     // (only while some are missing), work on the current repair, the yard a job is going to for repairs
        "crew": 4, "foodRemainderKg": 0.3, "waterRemainderKg": 0.6, "farmRemainderKg": 0.1, "crewGrowthS": 120.5,  // v14; each omitted when 0
        "legacyNoCrew": false,                       // v14: only written (true) for craft from older saves: no crew rules
        "dockClaimStationId": 2, "dockClaimPort": 0, // #55 (still v14, optional): the berth this craft has claimed; omitted when none
        "transit": { "startTick": 900, "arriveTick": 4300, "start": { "x": 1.0, "y": 2.0 },  // v15, optional: an abstract travel leg (#17)
                     "targetBodyId": 0, "targetCraftId": 2, "angleRad": 0.5, "radiusM": 215 }, // ends beside the target craft or body; omitted when flying for real
        "refiningBatch": { "recipeId": "smelt_iron", "inputsKg": { "iron_ore": 1000 }, "progressKg": 420.0 },  // v7
        "job": { "spotBearingRad": 1.2, /* #55, optional: this trip's landing spot */ "sourceBodyId": 2, "materialId": "metal", "destinationId": 2, "returnFraction": 0.25,
                 "active": true, "state": "Mining", "resumeState": "ToSource", "waitReason": null,
                 "completedCycles": 3, "deliveredKg": 30000 },  // v6, omitted when the craft has none
        "railOrbit": null,                           // v3: { parentId, radiusM, periodS, phaseAtZeroRad } for stations/parked ships
        "inventoryKg": { "metal": 4800 },            // v3: whole kg; omitted when empty
        "kits": [ { "id": 4, "name": "Surface depot #4", "design": { /* snapshot */ },
                    "materialsKg": { "metal": 3500 /* ... */ } } ],   // v11: construction kits held; omitted when none
        "requestsKg": { "metal": 20000 },            // v11: station requests "keep at least"; omitted when none
        "buildQueue": [ { "orderId": 2, "shipName": "Starter prospector #2", "design": { /* snapshot */ },
                          "materialsKg": { "metal": 12600 /* ... */ }, "progressKg": 3100.0 } ] }  // v3; omitted when empty
    ]
  }
}
```

The load checks for: the right `game`, a `schemaVersion` from 1 to 19, valid JSON, a non-negative tick, unique IDs, orbit parents that exist and aren't circular (bodies may appear in any order), valid designs (as a ship or as a station; queued designs as ships), known materials in inventories and orders, target, landed-on, rail-orbit parent and player IDs that exist, dock links to real free ports (one ship per port, not also landed or on rails), and anchor states the rules allow (anchored only while landed with a clamp or foundation; a landed foundation always anchored). Any failure raises `FormatException` with a reason.

## Changing the format

Older saves are upgraded by `scripts/save/SaveMigrations.cs` (#26): one step per version, applied to the raw JSON in order (v1→v2→…→current) before reading, so the loader only reads the current format. To change the format: bump `SaveGameSerializer.SchemaVersion`, add exactly one step (even if it changes nothing), and update this document. A test checks that every older version has a step. A version newer than this build is refused with a message.
