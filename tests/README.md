# tests

`Simulation.Tests/` is a plain .NET 8 xUnit project with no Godot runtime. It compiles the sources directly, so if that code ever references Godot, this build fails.

```powershell
dotnet test tests/Simulation.Tests
```

It links `scripts/simulation/` and `scripts/construction/`, and loads the real files in `data/`. Current coverage: deterministic sector generation, stable body and craft IDs, tick counts that don't depend on frame rate, the per-frame tick cap, on-rails orbits, radius derived from mass, part catalog and design loading and validation, design stats, and the flight model (thrust/mass, inertia, brake without overshoot, turning, input clamping, exact replay of a scripted input sequence), and rendezvous: orbit velocity, a target-relative brake that holds position on a curving orbit, closing-speed sign, and an asteroid slow enough to catch for several seeds. Save/load: full-state round trip, byte-identical save→load→save, saving and loading at several ticks then continuing exactly like a run that never stopped, saved bodies taking priority over the generator, stable IDs, and clear rejection of foreign, future-version or inconsistent files. Collision: the bounding radius, landing, riding along on the moving asteroid, lift-off rules, fast impacts, never ending a tick inside a body over 40,000 random ticks, saving while landed, and loading v1 saves. Blueprint editor: live stats, errors and warnings, bounds, undo per action and per drag, dirty tracking, design JSON round trip, ids from names, and designs with unknown parts. Materials: catalog loading, the rule that part costs equal part mass, rejection of bad costs with reasons, and the starter ship's bill of materials (and that it equals the ship's mass). Fabrication: the new-game setup, a yard that stays on its orbit, orders taking exactly their bill, building at the fabrication rate, parking next to the yard and leaving the parking orbit, refusals with the exact shortfall, cancel refunds, exact material conservation at every tick, design snapshots, save mid-build then continue, v2 save migration, and all-or-nothing inventory changes. Anchoring: the starter's clamp, staying anchored to the moving asteroid under thrust until released, refusals with reasons, foundations that are permanent and cheaper (and not allowed on ships), anchor/release changing nothing else, saving while anchored, rejecting impossible anchor states, and older saves with landed foundations. Rotation: facing directions, forward-only thrust, design JSON with `rot`, v1 design files, editor rotation and role detection. Docking: targeting craft, brake matching a station, dock range and speed limits, holding at the berth nose-in, undocking, built ships filling ports, and save/load (including one ship per port). Cargo: exact transfers, capacity, needing a dock, cargo slowing the ship, conservation over 500 random transfers, and save/load. Stations: building orbital stations and fixed structures on a chosen body (anchored and upright), the landing site requirement, material conservation, and queued landing sites in saves.

Planned, from `docs/02_TECHNICAL_ARCHITECTURE.md`: mass-ledger conservation, save/load round trips, depleted deposits, and offscreen/foreground equivalence.

`tests/.gdignore` keeps the Godot editor from scanning this folder. The main `SpaceAutomationSandbox.csproj` excludes `tests/**` from compilation.
